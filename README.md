# QazProcure Analytics

Аналитика госзакупок Казахстана: загрузка OWS v3, локальное хранилище, вопросы на русском и казахском, проверяемые расчеты и графики. Охват организаций и лет задается в `config/scope.json`.

## Развертывание в контейнерах

Нужны Docker Engine с Compose и доступ к OWS. Создайте каталог `secrets` и три файла без кавычек: `secrets/postgres_password` со случайным паролем БД и `secrets/ows_token` с рабочим токеном OWS, а также `secrets/google_api_key` с ключом Gemini. Файлы исключены из Git и контекста сборки образа. В Linux ограничьте права на чтение владельцем. В PowerShell можно создать пароль командой:

```powershell
New-Item -ItemType Directory -Force secrets | Out-Null
[System.IO.File]::WriteAllText((Join-Path (Get-Location) 'secrets/postgres_password'), ([Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(48))))
```

Токен OWS поместите в `secrets/ows_token` без вывода в журнал или терминал. Затем:

```powershell
docker compose up --build -d
docker compose ps
Invoke-RestMethod http://127.0.0.1:8765/api/health
Invoke-RestMethod http://127.0.0.1:8765/api/status
```

Интерфейс и API доступны только на `127.0.0.1:8765`. API, worker и PostgreSQL запускаются отдельно; данные PostgreSQL сохраняются в именованном томе `postgres_data` при перезапуске контейнеров. Worker получает токен OWS через смонтированный secret после сборки, API его не получает. Пароль БД также читается из secret при запуске. Не удаляйте том, если данные нужны; резервную копию и восстановление PostgreSQL организуйте в эксплуатационной среде. Проверяйте `/api/status` и `/api/quality` после первоначальной загрузки и далее для контроля свежести и ошибок. Портал может быть недоступен, а полный backfill займет значительное время.

Если локальный порт 8765 занят, задайте `API_PORT` в окружении Compose перед запуском и проверяйте API на выбранном порту.


## Развертывание в Kubernetes

Манифесты запускают PostgreSQL, API и worker. API использует Gemini; ключ монтируется из Secret, модель задаётся в ConfigMap.


```bash
docker build -t qazprocure:local .
kubectl apply -f k8s/namespace.yaml
kubectl create secret generic qazprocure-secrets -n qazprocure \
  --from-literal=postgres_password='<пароль>' --from-literal=ows_token='<токен OWS>' --from-file=google_api_key=secrets/google_api_key \
  --dry-run=client -o yaml | kubectl apply -f -
kubectl apply -k k8s/
kubectl -n qazprocure get pods
```

Манифесты проверены сборкой `kubectl kustomize k8s/` (валидный YAML, ресурсы собираются без ошибок) и синтаксическим разбором; живого применения на кластере в этой среде не было — здесь нет поднятого Kubernetes (Docker Desktop Kubernetes не включён, `kubectl get nodes` не отвечает). Перед продакшн-использованием нужно явно отработать: Ingress/TLS на границе организации, политику сетевой изоляции, бэкап PostgreSQL (manifest хранит данные в PVC без снапшотов) и ResourceQuota/HPA при необходимости — ни один из этих пунктов в манифестах не настроен.

## Локальный запуск без контейнеров

Нужен установленный Python 3.12+. Скопируйте `.env.example` в `.env` и заполните `OWS_TOKEN`, `GOOGLE_API_KEY`, `GEMINI_MODEL`; для модели используйте `LLM_PROVIDER=gemini`. Существующий `.env` не перезаписывайте.

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.lock.txt   # Linux/macOS: .venv/bin/python
.venv/Scripts/python.exe -m app.cli init
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

Интерфейс: [http://127.0.0.1:8765](http://127.0.0.1:8765). Описание API: [http://127.0.0.1:8765/docs](http://127.0.0.1:8765/docs). База по умолчанию — `data/procurement.db`.

## Загрузка данных

В отдельном окне запустите постоянный загрузчик:

```bash
.venv/Scripts/python.exe -u -m app.cli worker
```

Он продолжает сохраненные курсоры первоначальной загрузки, затем выполняет обновления. Интервал задается `SYNC_INTERVAL_HOURS` в `.env` (по умолчанию 6 часов). Для автозапуска при старте системы используйте штатные средства ОС (Планировщик заданий Windows, systemd, cron) либо запускайте `app.cli worker` как `worker`-сервис через Docker/Kubernetes (см. выше) — это и есть предусмотренный ТЗ путь для постоянно работающего сервиса.

Разовые команды:

```bash
.venv/Scripts/python.exe -m app.cli sync
.venv/Scripts/python.exe -m app.cli sync --mode incremental
.venv/Scripts/python.exe -m app.cli quality
# Дополнительные аналоги по нужному коду ЕНС ТРУ
.venv/Scripts/python.exe -m app.cli peers --enstru 282932.500.000001 --years 2024 2025 2026 --max-pages 10
```

Одновременно работает один загрузчик на базу. Закрытие терминала прерывает процесс, но сохраненные страницы остаются. Проверяйте полноту и свежесть через `/api/status` и `/api/quality`: завершение загрузки не гарантирует полноту исходного портала. Регулярное обновление требует включенного компьютера (или контейнера) и доступа к OWS.

## Вопросы и настройки

Например: «Покажи договоры за 2026 год», «Найди отклонения цены больше 30%», «Сравни закупки за 2024–2026 годы», «Оцени цену лота №…». Для однозначного отбора используйте точные параметры в интерфейсе; при включении они имеют приоритет над текстом. Результат показывает фактически выполненный запрос и сообщает об изменении вопроса после расчета.

В примерах ответа указаны ID позиции и договора, дата подписания, БИН заказчика, КАТО места поставки, цена/количество и ссылка на договор, когда эти поля известны. Сводные группы показывают объём и сумму рядом со средневзвешенной ценой.

Для маршрутизации через Gemini задайте в `.env` `LLM_PROVIDER=gemini`, `GOOGLE_API_KEY` и `GEMINI_MODEL`. В режиме `LLM_PROVIDER=rules` поддерживаются типовые формулировки. Модель выбирает параметры; арифметика выполняется кодом. В Gemini передаются вопрос и предыдущие параметры, а не договоры или содержимое базы.

`.env`, токены, ключи и база содержат рабочие данные: не публикуйте их. API запускается на локальном адресе; внешний доступ и авторизация не настроены.

## Соответствие ТЗ и результаты проверки — 24 октября 2026

Основные функции реализованы: OWS v3 → реляционное хранилище → нормализация → аналитика Python/SQL → ответы RU/KZ. Настроены все 27 БИН из ТЗ и 2024–2026 годы. Пройдены 162/162 основных раздела загрузки планов и договоров; это не доказывает полноту связанных сущностей и исходного портала. Текущие пропуски связей, ошибки и свежесть доступны в `/api/quality`.

Повторный локальный прогон: **102 Python-теста прошли**, проверка визуализаций RU/KZ прошла. Сохранённая проверка текущего Gemini: **12/12 ответов, 64/64 размеченных факта** ([протокол](submission/gemini_current_smoke.json)). Полный прогон 114 вопросов для текущей Gemini-версии пока не подтверждён; прежние результаты другого провайдера не подтверждают её точность. Малый набор проверяет только размеченные факты и не заменяет полную приёмку требования ≥85%.

Дополнительно выполнены два живых запроса через `/api/chat` с Gemini: поиск лота на русском (15,97 с) и поиск трёх ценовых аномалий >30% за 2026 год на казахском (89,55 с). Оба прошли: факты поиска сверены с исходным OWS payload, средневзвешенные цены и отклонения трёх примеров пересчитаны из SQL по возвращённым ID аналогов. Полнота выбора аналогов этой проверкой отдельно не подтверждается. [Вопросы, ответы и результаты сверки](submission/manual_agent_checks_20261024.json). Время широкого запроса на аномалии остаётся заметным ограничением; эти два случая не заменяют полный factual-прогон.

Fair Price использует сопоставимые ЕНС ТРУ, место поставки, эмпирический временной тренд и сезонность. Регионально-временная модель применена на реальном примере с 439 аналогами, включая 194 аналога того же города; индивидуальные поправки проверены отдельным пересчётом ([пример](submission/regional_core_example.json), [проверка](submission/regional_independent_check.json)). Медианная ошибка на отложенных месяцах — 30,79%; тренд не является официальным ИПЦ. Для лотов с недостатком сопоставимых данных агент выдаёт предварительный ориентир либо сообщает о недостатке данных. Подробности — в [методологии](docs/methodology.md).

Инкрементальная загрузка и обход публикаций реализованы, но **задержка ≤24 часов от публикации для всего охвата пока не подтверждена**. Свежесть последней загрузки и задержка публикации — разные показатели. Метрика публикаций учитывает только уже загруженные объявления; отрицательные задержки исключаются и показываются отдельно. Для текущего источника настроен UTC+5 (`OWS_PUBLICATION_UTC_OFFSET_MINUTES=300`, [свидетельство](submission/source_timezone_evidence.json)); пустое значение отключает предположение о часовом поясе. Нужны дальнейшие наблюдения и проверка полноты охвата.

Docker проверен с реальной ограниченной загрузкой OWS и сохранностью PostgreSQL после перезапуска ([протокол](submission/docker_smoke.json)). Kubernetes проверен сборкой манифестов; живое развёртывание на кластере не проверено. API использует внешний Gemini и требует исходящего доступа к Google: контейнерное размещение приложения не означает полностью автономную работу без интернета. Автоматическая подмена модели шаблонами отключена.

Открытые условия: полный factual-прогон Gemini, доказательство SLA публикаций, проверка Kubernetes на кластере и контроль отсутствующих связей данных. Подробная [матрица соответствия](docs/compliance.md), [покрытие](docs/coverage.md) и [риски](docs/risks.md).
