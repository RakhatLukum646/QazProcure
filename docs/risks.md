# Риски и ограничения

Актуализировано 24 октября 2026. Документированные ограничения не означают выполнение соответствующих требований ТЗ.

## Данные и источник

- OWS может быть недоступен; ошибки авторизации и временные ошибки обрабатываются ограниченными повторными попытками.
- Покрытие основных разделов Plans/Contract — 162/162. Это завершение обхода страниц, а не доказательство полноты всех сущностей портала.
- Связи с планами проверены отдельно: 2 244 позиции ссылаются на 1 938 отсутствующих ID. Все 1 938 ID повторно запрошены в OWS, ни один не возвращён, ошибок нет. Это недоступность через использованный API на момент проверки, не доказательство физического удаления. Протокол: [missing_plans_audit.json](../submission/missing_plans_audit.json).
- Счётчики связей относятся ко всем сохранённым позициям охвата, а не только последним подписанным версиям. Наличие активного плана не равно пригодности для аналитики: отдельно фильтруются версии, статусы, валюта, цена, количество и реквизиты плана. См. [покрытие](coverage.md).
- Физически исчезнувшие объекты без флага удаления требуют периодической сверки с источником; текущий worker такую полную сверку не гарантирует.

## Актуальность: требование ≤24 часа не подтверждено

Свежесть последней успешной загрузки не измеряет задержку от публикации каждой записи. Worker поддерживает инкрементальные обновления, но для эксплуатации должен постоянно работать на сервере.

`announcement_publication_lag` использует неизменяемое `first_seen.seen_at` и только публикации после завершения backfill и появления `first_seen_epoch`. Ранее `raw_objects.fetched_at` перезаписывался повторной загрузкой и давал ложные задержки; затем отрицательная разность дат обнулялась и давала ложные нулевые задержки. Эти способы оценки больше не используются.

Текущий часовой пояс publishDate подтверждён как UTC+5: время публикации совпадает с официальной страницей, серверные часы портала отличаются от HTTP Date на 300 минут. Доказательство: submission/source_timezone_evidence.json. По умолчанию используется 300; явное пустое значение отключает интерпретацию дат без смещения. Даты с явным смещением обрабатываются напрямую; отрицательные задержки считаются ошибочными наблюдениями и показываются отдельно, а не превращаются в ноль. Общие правила времени портала не доказывают формат конкретного поля API.

Метрика видит только уже полученные объявления. Никогда не полученные публикации ей неизвестны; у договоров/планов/лотов нет аналогичного поля публикации. Даже положительные результаты этой метрики не подтверждают SLA всего охвата. Текущее состояние: [quality_report.json](../submission/quality_report.json).

## Fair Price и объёмы

- Сравнительный Fair Price работает при достаточных аналогах других заказчиков того же города, описания, кода, единицы, типа и размера партии.
- Региональная/временная модель теперь активируется на реальных данных основной базы: лот 42570523, 439 договоров-аналогов, 194 в том же городе, оценка 283955.67 KZT. Протокол: submission/regional_core_example.json. Ошибка на отложенных шести месяцах: медиана 30.79%, P90 61.26%; это статистический ориентир с существенной неопределённостью, не точный прогноз рыночной цены.
- При недостаточной истории используется тот же год и квартал, статус `provisional`. Это не учёт инфляции и не подтверждённая региональная калибровка для такого лота. При достаточной истории используется совместная модель город/месяц; официальный ИПЦ не подменяется эмпирическим трендом.
- Рост количества — отклонение от истории, а не доказательство завышенной потребности: нет сведений о штате, запасах и потреблении. Сравнение текущего и прошлых лет теперь использует одинаковое календарное окно; исправление покрыто регрессионным тестом.
- При превышении 200 000 строк текущая аналитика прекращается с явной ошибкой. Для более крупного охвата требуется перенос агрегаций в SQL/материализованные витрины.

## Точность и воспроизводимость


В приёмочном режиме `--workers` теперь действительно управляет параллельными вызовами LLM; расчёты и сохранение в SQLite выполняются последовательно. Блокировка файла исключает двух писателей одного отчёта. Старые прогоны этой блокировки не имели.

## Развёртывание и безопасность

- Docker проверен заново на отдельной базе: сборка, старт API/PostgreSQL, ограниченная загрузка реальных OWS данных, перезапуск, сохранность счётчиков. [Протокол](../submission/docker_smoke.json). Это ограниченная проверка, не полный backfill в контейнере.
- Kubernetes: `kubectl kustomize` собирает манифесты; текущий context отсутствует, применение к кластеру не выполнялось. Готовность конфигурации не равна проверенной эксплуатации.
- Секреты передаются файлами; OWS-токен получает только worker. Полный аудит безопасности не проводился.
- TLS, пользовательская аутентификация, сетевые политики, резервное копирование, HPA/ResourceQuota остаются задачами инфраструктуры. Эти дополнительные меры не выдаются за отдельные обязательные пункты исходного ТЗ.

## Последняя перепроверка

Полная регрессия: 102 теста. Повторный Gemini-прогон текущей версии столкнулся с ConnectError: старые 100% нельзя выдавать за новый успешный прогон. Локальная модель проверена отдельным полным прогоном. Обход публикаций за фиксированные 24 часа перечислил все 5922 записи API, из них 40 входят в охват; submission/publication_sweep.json. Наблюдаемые задержки 19 новых объявлений: максимум 2.57 часа, 0 свыше 24 часов (24 октября 2026). Это ограниченное наблюдение, не долгосрочная гарантия SLA.

Текущий провайдер: Gemini. Задайте GOOGLE_API_KEY и GEMINI_MODEL. Автоматическая подмена модели шаблонами отключена. Для контейнерного API ключ читается из secrets/google_api_key; Kubernetes Secret содержит google_api_key. Данные и расчёты остаются в хранилище приложения; Google получает вопрос и параметры для маршрутизации. Требуется исходящий доступ к API Google.
